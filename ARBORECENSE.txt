Arborescence fonctionnelle du programme webserv
================================================

1) Point d'entree : main.cpp
----------------------------

main(argc, argv)
  - verifie le nombre d'arguments
  - choisit le fichier de config :
      - argv[1] si present
      - config/conf_default sinon
  - cree un objet ConfigParser parser(configPath)
  - parse le fichier de configuration
  - recupere la config finale via parser.getConfig()
  - configure les signaux :
      - SIGPIPE ignore
      - SIGINT => handleStopSignal
      - SIGTERM => handleStopSignal
  - cree un objet Server server(config)
  - pour chaque serveur dans config.servers :
      - verifie si le host:port a deja ete ajoute
      - si non : server.addListener(host, port)
      - sinon : erreur duplicate listen directive
  - lance le serveur : server.run()
  - gestion des exceptions :
      - affiche "Parser error: ..."
      - return 1
  - return 0


2) Gestion du parsing de config
--------------------------------

ConfigParser::ConfigParser(configFile)
  - ouvre le fichier
  - lit les tokens
  - appel parse(tokens)

ConfigParser::parse(tokens)
  - boucle sur les tokens
  - detecte :
      - server { ... }
      - location ... { ... }
  - appelle :
      - parseServer(...)
      - parseLocation(...)

ConfigParser::parseServer(server, tokens, pos)
  - initialise le serveur
  - appelle les parsers de directives serveur :
      - parseListen(server, ...)
      - parseServerName(server, ...)
      - parseClientMaxBodySize(server, ...)
      - parseErrorPage(server, ...)

ConfigParser::parseLocation(location, tokens, pos)
  - initialise le location
  - appelle les parsers de directives location :
      - parseRoot(location, ...)
      - parseIndex(location, ...)
      - parseClientMaxBodySize(location, ...)
      - parseAllowedMethods(location, ...)
      - parseAutoIndex(location, ...)
      - parseUploadDir(location, ...)
      - parseCgi(location, ...)
      - parseReturn(location, ...)

ConfigParser::getConfig()
  - retourne le Config final


3) Creation des sockets d'ecoute
---------------------------------

main() -> server.addListener(host, port)
  - appelle Server::ListeningSocket(host, port)
      - cree un socket TCP
      - configure l'adresse
      - bind()
      - listen()
  - appelle setNonBlocking(fd)
      - fcntl(fd, F_SETFL, O_NONBLOCK)
  - ajoute le fd dans _listenFds
  - ajoute un pollfd dans _pollFds
  - stocke host/port dans _listenerHosts et _listenerPorts


4) Boucle principale du serveur
-------------------------------

Server::run()
  - verifie s'il y a des sockets ouverts
  - tant que !g_stop :
      - poll(_pollFds)
      - si poll retourne un evenement :
          - checkTimeouts()
          - checkCGITimeouts()
          - pour chaque fd :
              - si evenement sur un listener -> handleNewConnection(fd)
              - si evenement sur un CGI fd -> handleCGIRead / handleCGIWrite
              - si evenement sur un client -> handleRead / handleWrite
              - si fermeture ou erreur -> closeClient(index)
      - compactPollFds()


5) Gestion des connexions clients
----------------------------------

Server::handleNewConnection(listenFd)
  - accept()
  - cree ou initialise un Client
  - ajoute le client dans _clients
  - ajoute le fd client a _pollFds
  - marque le client actif

Server::handleRead(index)
  - lit les donnees du socket client
  - construit le rawRequest
  - appelle parseRequest(rawRequest)
      - parse les headers HTTP
      - identifie la methode (GET / POST / DELETE)
      - gere le body et les chunks
      - detecte requestComplete
  - appelle selectServerConfig(listenFd, req)
      - trouve le bon server selon host + port
  - appelle matchLocation(path, serverConfig)
      - determine le location correspondant
  - appelle resolvePath(urlPath, location)
      - construit le chemin filesystem
  - appelle buildResponse(client, req)
      - genere la reponse HTTP
  - appelle setClientPollout(clientFd)
      - active POLLOUT pour repondre au client

Server::handleWrite(index)
  - envoie outBuffer au client
  - si tout est envoye :
      - closeClient(index)

Server::closeClient(index)
  - ferme le socket client
  - nettoie les ressources CGI associees
  - tue le processus CGI si actif
  - ferme les FDs CGI
  - supprime le client de _clients
  - met _pollFds[index].fd = -1


6) Parsing d'une requete HTTP
-----------------------------

Server::parseRequest(rawRequest) const
  - lit la ligne de la requete
  - parse method, path, version
  - parse headers HTTP
  - recupere le body si present
  - gere les chunks si Transfer-Encoding: chunked
  - retourne un objet Request


7) Choix du server et du location
----------------------------------

Server::selectServerConfig(listenFd, req) const
  - compare host:port avec les serveur configures
  - retourne le bon ServerConfig

Server::matchLocation(path, serverConfig) const
  - compare le chemin URL avec les locations
  - cherche la meilleure correspondance
  - retourne le LocationConfig associe

Server::resolvePath(urlPath, location) const
  - construit le chemin du fichier sur disque
  - prend en compte le root et le location


8) Construction de la reponse HTTP
----------------------------------

Server::buildResponse(client, req)
  - appelle la logique HTTP
  - renvoie une reponse HTTP complete

Response::build(req, config)
  - determine la route et le bon location
  - switch sur la methode HTTP :
      - GET -> handleGET(...)
      - POST -> handlePOST(...)
      - DELETE -> handleDELETE(...)
  - construit la reponse finale avec :
      - makeResponse(...)
      - makeRedirect(...)
      - errorResponse(...)

Response::handleGET(req, location, config)
  - resolvePath(urlPath, location)
  - si c'est un dossier :
      - index si present
      - autoindex si active
      - sinon erreur 403/404
  - si c'est un fichier :
      - lit le contenu
      - trouve le MIME via getMime(path)
      - genere une reponse 200
  - si chemin invalide :
      - erreur 404

Response::handlePOST(req, location, config)
  - traite les donnees envoyees
  - gere les uploads / CGI / scripts
  - renvoie code HTTP adapte

Response::handleDELETE(req, location, config)
  - supprime le fichier si autorise
  - renvoie 200 OK ou erreur

Response::makeResponse(code, mime, body, contentDisposition)
  - construit le header HTTP
  - ajoute :
      - HTTP/1.1 status
      - Content-Type
      - Content-Length
      - Connection
      - autre header optionnel
  - retourne le message complet

Response::errorResponse(code, config)
  - cherche la page d'erreur correspondante
  - construit la reponse d'erreur HTTP

Response::statusText(code)
  - retourne le texte associe au code HTTP (200 OK, 404 Not Found...)


9) Gestion des CGI
------------------

Server::findCgiTarget(req, config, interpreter, scriptPath) const
  - determine si la route demande un CGI
  - trouve l'interpreteur (python, php, etc.)
  - trouve le script cible

Server::startCGI(clientFd, interpreter, scriptPath, method, query, requestUri, body, headers, serverName, serverPort)
  - cree un fork
  - dans le processus enfant :
      - prepare env CGI
      - dup2 stdin/stdout vers les pipe
      - execve(interpreter, scriptPath)
  - dans le parent :
      - garde les pid et fd
      - ajoute les fd CGI dans _pollFds
      - stocke la relation _CGIToClient

Server::handleCGIRead(index)
  - lit la sortie du CGI
  - stocke les donnees dans le client
  - si CGI termine : finishCGI(clientFd)

Server::handleCGIWrite(index)
  - ecrit le body dans l'entree du CGI

Server::handleCGIError(index)
  - gere les erreurs du CGI
  - ferme le processus et la connexion

Server::finishCGI(clientFd)
  - termine la communication CGI
  - transforme la sortie CGI en reponse HTTP
  - active l'envoi au client


10) Timeouts et nettoyage
-------------------------

Server::checkTimeouts()
  - verifie les clients inactifs depuis trop longtemps
  - ferme les sockets trop vieux

Server::checkCGITimeouts()
  - verifie si un CGI depasse CGI_TIMEOUT
  - tue le process
  - nettoie le client

Server::~Server()
  - pour chaque client :
      - si CGI actif :
          - kill(CGI pid, SIGKILL)
          - waitpid(...)
      - ferme les fd CGI
      - ferme la reponseFileFd
      - close(socket client)
  - ferme tous les sockets d'ecoute


11) Resume en une ligne
----------------------

main -> parser config -> creer Server -> addListener -> run poll loop -> accept clients -> parse request -> choose server/location 
-> build response -> CGI si besoin -> send response -> timeout/cleanup -> fin du programme

Conclusion
----------
Le programme se deroule ainsi :

main.cpp
  -> parse config: via parser/configParser.hpp et parser/configParser.cpp
  -> creer listeners: server/server.hpp et server/socket.cpp
  -> demarrer la boucle event-driven avec poll: server/server.cpp
  -> accepter les clients: server/server.cpp
  -> lire la requete HTTP: server/handleOperation.cpp et server/server.cpp
  -> choisir le bon server/location: server/server.cpp
  -> construire la reponse: HTTP/HTTP.hpp, HTTP/HTTP.cpp et HTTP/response.cpp
  -> executer un CGI si necessaire: server/handleCGI.cpp et CGI/start.cpp
  -> envoyer la reponse via server/handleWrite(): server/server.cpp
  -> nettoyer les ressources: server/server.cpp et server/checkTimeout.cpp
  -> quitter proprement au niveau de main.cpp et du destructeur Server::~Server()
